# 나중에 등록한 선수의 계측 수집

## 확인된 원인

2026-10-25 실제 설정에서 배번호 30703과 101은 앱의 Full 코스에 등록되어 있었다.
공개 계측 페이지에서는 30703이 10K, 101이 EF(엘리트 풀코스)였다.
제공처 종목이 일치하지 않아 수집이 거절되었지만, 선수별 오류를 보존하지 않아
출발 후 45분이 지나면 화면에는 계측 지연으로만 표시되었다.

30703은 10km 코스로 이동하고 해당 코스를 10K에 연결해야 한다.
101은 EF에 대응하는 종목을 별도로 등록해 연결해야 한다. 같은 거리라도 Full과 EF를
자동으로 합치지 않는다. 특히 실제 출발 시각이 다른 기록을 잘못된 기준으로 가져오지 않는다.

## 수정

- 수집 대상을 UUID 커서 순회 대신 마지막 확인 시각이 없는 선수부터, 이후에는
  가장 오래 확인한 선수부터 선택한다. 한 번에 40명, 동시 요청 4개 제한을 유지한다.
- 선수별 마지막 확인 시각, 성공·대기·실패 상태, 오류 코드와 실제 제공처 종목을 저장한다.
- 종목 불일치를 ‘종목 확인 필요’로 표시하고 실제 종목·현재 연결 및 정정 경로를 안내한다.
- 계측이 없는 상태를 ‘첫 계측 수집 대기’로 구분한다. 이 표시가 DB의 running 상태나
  다음 수집을 막지 않는다. 늦게 등록한 선수도 출발부터의 과거 계측을 받아올 수 있다.
- 일부 선수만 실패한 수집도 최근 수집 시각을 갱신하며 성공한 선수의 기록은 반영한다.
- 기존 3분 자동 갱신·1분 최소 간격·45분 추정 중지 정책은 유지한다.

035 이후 `supabase/migrations/036_tracking_entry_sync_status.sql`을 적용하고 앱을 배포한다.
기존 계측은 보존하고 마지막 수신 시각으로 확인 시각을 초기화한다. 운영 설정을 자동 변경하지 않는다.

검증: `npm run test:tracking`, `node scripts/test-tracking-staff-api.mjs`,
`node scripts/test-tracking-timing-database.mjs`, `node scripts/test-tracking-ui-browser.mjs`.
