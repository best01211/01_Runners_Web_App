# 실제 대회 추적: 수동 계측 단계

## 제공 기능
- 대시보드 **대회 선수 추적** → 이벤트 목록 → 추적 화면
- 기존 이벤트 참가 신청자와 회원 계정을 연결한 배번호 등록
- 운영진의 GPX / GeoJSON 업로드, 공식 거리와 예정 출발 시각 설정
- 수동 START / 중간 체크포인트 / FINISH 기록 저장
- 저장된 기록을 15초마다 조회하고 그 사이 예상 위치를 보간
- 연결 실패 시 마지막 표시 위치 고정, 미계측 45분 이후 추정 정지
- 운영진의 DNS / DNF / 주행 상태 관리
- START와 FINISH를 모두 측정한 경우에만 넷타임 표시

외부 계측 서비스와 GPS는 연결하지 않는다. FINISH 기록은 체크포인트로 보존하며,
예상 도착으로 완주 기록을 만들지 않는다. 기존 참가 상태·출석 점수·랭킹을 자동 변경하지 않는다.

## 최초 DB 적용
기존 003~005 마이그레이션이 적용된 프로젝트의 Supabase SQL Editor에서
supabase/migrations/006_race_tracking.sql 전체를 한 번 실행한다.
기존 profiles/schedules/참가 신청 데이터는 수정하지 않는다. 신규 테이블과 RPC·RLS만 생성한다.
migration은 하나의 트랜잭션이며, 이미 적용된 후 재실행하는 용도가 아니다.

새 테이블: race_courses / race_entries / runner_checkpoints.
PostgREST 스키마 캐시에 반영되면 화면에서 조회·저장이 가능하다.
로컬 앱의 service-role 키는 일반 SQL DDL 실행 권한을 제공하지 않으므로,
프로젝트 DB 연결이나 관리 API 접근 없이 앱에서 이 migration을 자동 실행할 수 없다.

## 서울레이스 연결 순서
1. 실제 대회 정보로 ‘이벤트’ 일정 생성 (기존 일정이 있으면 재사용).
2. 해당 일정 → 선수 추적 열기.
3. 운영진이 보유한 GPX와 공식 종목 거리, 출발 시각을 입력하고 코스 저장.
4. 회원이 기존 참가 신청을 하고 자신의 배번호를 등록하거나, 운영진이 신청자의 배번호를 등록.
5. 실제 확인한 통과 시각을 START → 중간 지점 → FINISH 순서대로 입력.
6. 다른 회원은 대회 추적 화면에서 계측 기반 예상 위치 조회.

GPX 파일은 브라우저에서 좌표만 파싱한다. 원본 파일은 업로드하지 않는다.
단일 연속 trkseg, GeoJSON LineString 또는 Feature(LineString)만 지원한다.
파일 최대 2MB, 좌표 최대 20,000개, 종목 거리 1~100km.
파일에서 계산한 좌표 거리도 표시한다. 공식 거리와 경로 차이는 운영진이 검토해야 한다.
추적 화면 표시 시각은 한국 시간이며, datetime-local 입력은 기기 시간대에 따른다.
서버는 ISO UTC로 저장한다. 코스 좌표는 공식 거리 비율로 매핑한다.

## 운영 범위
이 단계는 이벤트당 하나의 코스/종목·예정 출발 시각만 지원한다.
하프/10km 등 여러 종목을 동시에 운영하려면 이벤트를 분리한다.
배번호는 이벤트 내 중복 불가, 선행 0 유지. 회원당 한 출전 정보.
코스·출발 시각은 출전 등록이 생기면 고정한다.
배번호·목표 페이스는 계측 기록이 생기면 고정한다.
회원의 본인 출전 정보 수정은 예정 출발 전까지만 허용한다.
운영진은 계측이 시작되기 전까지 출발 이후에도 출전 정보를 보완할 수 있다.
취소한 참가 신청, 승인되지 않은 계정, 비활성 계정의 선수는 목록에서 제외한다.
기존 관리자 역할의 참가 신청 제한은 유지된다. 관리자는 참가 선수 등록·계측 관리를 수행한다.

계측 기록은 이 화면에서 수정·삭제하지 않는다. 잘못 저장한 기록의 정정은
별도 감사 이력과 정정 흐름을 추가하기 전까지 운영진의 DB 검토가 필요하다.
기록 입력 전에 시각·거리·대상 배번호를 확인한다.
순서 역전·중복 지점·미래 시각·코스 초과·2:00~20:00/km 밖의 실측 구간을 거절한다.
현재 대회당 500명, 선수당 100개 계측 기록까지 지원한다.
실측 START가 없는 FINISH는 완주 위치를 표시하지만 넷타임은 미확정으로 둔다.
계측 기록 수신 시각과 입력 운영진 ID는 서버에서 기록한다.

## 보안
API는 로그인·승인·활성 계정과 유효 이벤트를 검사한다.
조회 응답은 이메일·로그인 아이디를 포함하지 않고, 회원 참가자 선택은 본인으로 제한한다.
API는 service-role로 기존 참가/프로필을 확인하고 필요한 데이터만 반환한다.
변경은 사용자 세션으로 보안 정의 RPC를 호출한다.
RPC는 DB에서 auth.uid(), 역할, 계정 상태, 참가 신청, 이벤트 상태를 재검사한다.
일정 행을 잠가 코스 등록·출전 등록·계측 저장의 동시성 충돌을 막는다.
새 테이블은 RLS와 SELECT 전용 권한을 사용한다. 직접 INSERT/UPDATE/DELETE는 허용하지 않는다.
RLS의 출전 조회는 보안 정의 함수로 기존 참가 테이블의 정책과 독립적으로 자격을 검사한다.
브라우저 쓰기 요청은 동일 Origin만 허용한다.

## 검증
- npm run test:tracking: 엔진·코스·저장 입력 검증 30개
- PostgreSQL(WASM) 통합 검증: 권한·중복·계측 순서·완주·RLS 25개
- 전체 ESLint, TypeScript, 프로덕션 빌드
- 별도 로컬 DB에서 GPX 업로드 → 배번호 → START → FINISH 화면 검증

DB 테스트 재실행:
    npm install --prefix .test-output/sql-qa --no-audit --no-fund --ignore-scripts --cache .npm-cache @electric-sql/pglite@0.5.8
    node scripts/test-race-database.mjs

테스트 DB는 메모리 안에서 생성하며 연결된 Supabase 프로젝트의 데이터에 접근하지 않는다.
운영 타일 트래픽·공급자 용량과 외부 Timing Provider 연동은 다음 단계다.

## 모바일 화면
지도 → 가로 스크롤 선수 선택 → 선택 선수 거리·페이스·최근 계측 순으로 표시한다.
전체 선수 검색, 계측 이력, 운영진 입력은 접어서 둔다.
모바일 지도는 화면 높이에 맞춰 줄이고, 데스크톱은 우측 선수 목록을 유지한다.
버튼·입력은 터치 영역을 확보하고 입력 글꼴은 16px로 표시한다.
320px / 390px에서 검색·이력·입력 폼과 가로 넘침을 확인했다.

서울레이스 GPX 원본은 data/race-courses/2026-seoul-race-21k.gpx에 보관했다.
메타데이터: 2026서울레이스21k, 연속 트랙 1개, 918개 좌표.
좌표 누적 거리 약 21.655km는 GPX 경로 길이이며 공식 경기 거리가 아니다.
실제 등록 시 공식 거리와 예정 출발 시각을 별도로 확인한다.
모바일 검증 화면은 이 GPX와 별도 로컬 DB의 검증 선수로 확인했으며,
연결된 Supabase에 실제 코스·선수·기록을 등록한 검증은 아니다.

## 독립 추적 탭 (007 이후)
일정 생성·모집 종료·일정 참가 신청 없이 /tracking/new에서 대회와 GPX를 직접 등록한다.
등록 권한은 승인된 활성 관리자(admin)만 가진다. staff·회원은 조회만 가능하다.
라이브 추적 / 대회 등록(관리자 전용) / 가상 데모 탭으로 이동한다.
관리자는 승인된 활성 회원을 출전자로 선택하고 배번호·목표 페이스·계측·DNS/DNF를 등록한다.
보관된 서울레이스 GPX를 버튼으로 불러오거나 다른 파일을 선택할 수 있다.

Supabase SQL Editor에서 006 적용 이후 007_standalone_tracking.sql을 한 번 실행한다.
독립 테이블 tracking_races / tracking_race_entries / tracking_checkpoints와 관리자 RPC를 생성한다.
과거 일정 추적 RPC의 authenticated 실행 권한을 회수한다.
007이 적용돼야 새 DB 저장과 기존 직접 RPC의 권한 회수까지 완료된다.
기존 테이블의 데이터는 삭제하지 않는다. 기존 일정별 추적 페이지는 독립 목록으로 이동한다.

새 API: POST /api/tracking, GET·POST /api/tracking/{raceId}.
API의 관리자 검사와 DB 함수의 admin·active·approved 검사를 함께 적용한다.
독립 등록은 기존 일정 참가 제한이나 출석 점수 정책을 변경하지 않는다.
새 DB 통합 테스트는 node scripts/test-standalone-tracking-database.mjs로 실행한다.
기존 검증 25개 + 독립 등록·권한 검증 15개가 포함된다.

라이브 지도도 코스·선수 전용 배경으로 시작하며, 배경 지도 표시는 사용자가 선택한다.
