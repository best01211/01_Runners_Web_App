# 사진 정책 및 사용성 보완 — 2026-10-13

## 사진 정책

- 일정 생성·수정에서 대표 이미지와 코스 이미지 첨부를 제거했다. API에도 개별 이미지 URL을 보내더라도 저장되지 않는다.
- 정기런은 ‘일정 → 정기런 양식 관리’에서 등록한 여러 양식 중 하나를 선택한다. 양식명·기본 설명·장소·정원을 불러오고 양식의 사진을 재사용한다. 관리자와 운영진 모두 추가·수정·삭제할 수 있다. 4개로 개수를 고정하지 않는다. 번개런·이벤트·훈련은 사진 없이 표시한다.
- 내 정보에서 프로필 사진 선택·미리보기·저장이 가능하다. 대시보드에도 프로필 사진을 표시한다.
- 브라우저에서 WebP로 재인코딩한다. 프로필은 긴 변 최대 512px, 200KB 이하; 정기런 양식 사진은 긴 변 최대 1600px, 500KB 이하이다. 원본 입력은 JPG/PNG/WebP, 10MB 이하이다.
- 프로필은 사용자별 고정 파일, 양식 사진은 양식별 고정 파일을 덮어쓴다. 반복 교체로 새로운 파일이 누적되지 않는다. 캐시 갱신을 위해 URL에 버전을 붙인다.
- 업로드 API는 승인·활성 상태, 동일 Origin, 용도, 용량, WebP 헤더를 검사한다. 양식 사진 등록은 관리자·운영진만 가능하다. 프로필 API는 다른 회원 사진이나 외부 호스트의 새 URL을 거절한다. 기존 프로필 URL을 그대로 유지하는 경우는 허용한다.
- 다운로드 버튼과 별도 다운로드 API는 제공하지 않는다. 사진 표시에는 전송량이 발생한다. 공개 Storage URL의 브라우저 저장을 기술적으로 차단하는 기능은 아니다.

60명 프로필을 모두 최대 크기로 저장해도 신규 사진 파일은 약 12MB이며, 양식 사진 4장은 최대 약 2MB 수준이다. 이전 버전에서 이미 업로드된 UUID 파일은 삭제하지 않았다. 기존 파일을 정리하려면 사용 중인 URL을 확인하고 별도로 처리해야 한다.

## 사용성

- 공통 뒤로가기 버튼. 대기·계정 제한·점검 화면에서는 대시보드로 되돌아갔다가 같은 화면으로 다시 이동하는 버튼을 숨긴다.
- 일반 회원은 번개런만 선택할 수 있다. 게스트에게 일정 생성 버튼을 숨긴다.
- 일정 목록을 다가오는 일정과 지난 일정으로 분리한다. 유형·상태를 한국어로 표시하고 목록 조회 실패를 빈 목록으로 오인하지 않도록 오류 처리한다.
- 일정·프로필 입력에 라벨, 저장 중 입력 제한, 중복 제출 방지와 통신 실패 안내를 보완했다. 비밀번호 변경과 탈퇴도 처리 중 표시·실패 안내를 추가했다.
- 신청 기간을 15초마다 갱신한다. 정기런 그룹 미등록·출석 시작에 따른 제한을 안내한다. 모바일 그룹 생성 입력을 두 열로 배치한다.
- 공통 로딩·오류 재시도 화면을 추가했다. 입력 폰트를 16px로 지정하고, 기존 밝은 화면과 충돌하던 시스템 다크 모드 자동 적용을 제거했다.

## 적용과 검증

003~009 적용 후 `supabase/migrations/010_regular_run_templates.sql` 전체를 SQL Editor에서 실행한다. 010은 재실행해도 안전하도록 작성했다. 이후 일정 → 정기런 양식 관리에서 양식을 등록하고, 일정 만들기에서 선택 → 기본 정보 불러오기 → 날짜·시간 입력 → 저장한다. 기존 일정은 보존되며, 기존 정기런에 사진을 연결하려면 일정 수정에서 양식을 선택한다.

첫 사진 정책 변경에서는 인증 5개, 출시/안정화/사진 정책 23개, 추적 30개 단위 테스트, ESLint, TypeScript 및 프로덕션 빌드가 통과했다. 여러 양식 지원 변경에서는 출시/안정화/사진/양식 25개 단위 테스트, 새 양식 DB 28개 검사와 기존 안정화 DB 46개 검사가 통과했다. 로컬 프로덕션 서버에서 비밀번호 변경 완료 안내와 가입 화면 뒤로가기 링크를 확인했다.

실제 회원 로그인, 사진 업로드·교체, 공통 사진 표시 및 모바일 화면은 운영 계정으로 최종 확인이 필요하다. 이번 작업에서는 운영 DB에 사진·회원·일정을 쓰지 않았다.

## 양식 변경·삭제 정책

양식의 이름·설명·장소·정원 수정은 다음에 불러올 기본값을 바꾼다. 이미 만든 일정의 텍스트·날짜·참가 기록을 자동 변경하지 않는다. 양식 사진은 해당 양식을 사용하는 기존 일정에도 변경 내용이 반영된다.

양식 삭제는 새 일정에서 불러오는 목록에서 제외하는 방식이다. 기존 일정에 필요한 양식과 사진은 보관한다. 삭제된 양식을 다른 일정에 새로 연결하는 요청은 API와 DB 트리거에서 모두 거절한다. 기존 일정은 삭제된 양식을 계속 유지하거나 다른 활성 양식으로 바꿀 수 있다. 일반 회원은 양식을 조회할 수 있지만 변경은 허용된 운영 API를 통해 관리자·운영진만 가능하다. 직접 DB 쓰기 권한은 허용하지 않는다.

이전 단일 공통 사진 설정과 파일은 삭제하지 않았다. 새 양식은 별도 사진 경로를 사용한다. 운영 DB 변경과 사진 업로드는 이번 작업에서 실행하지 않았다.
