# 참가·출석·운영 관리 개선 적용 안내

## 적용 순서

020은 이미 실행한 상태에서 다음 파일을 Supabase SQL Editor에서 순서대로 실행한다.

1. supabase/migrations/021_activity_workflow.sql — 자동 종료 함수·종료 시각 검사·댓글 삭제 주체·시즌 수정·관리자 계정 조회 제한.
2. supabase/migrations/022_attendance_cron.sql — pg_cron 활성화 및 1분 간격 자동 출석 종료 예약.
3. supabase/diagnostics/activity-workflow.sql — 함수·권한·예약 작업 및 최근 실행 결과 확인.
4. 브라우저 새로고침 후 테스트 일정으로 확인.

SQL은 아직 운영 DB에서 실행하지 않았다. 021을 적용하기 전에는 새 출석·댓글 삭제·시즌 설정 일부 기능이 동작하지 않는다. 022를 적용해야 화면을 닫아도 자동 종료된다. 설치 근거: [Supabase Cron 설치](https://supabase.com/docs/guides/cron/install), [작업 예약](https://supabase.com/docs/guides/cron/quickstart).

## 자동 출석 종료

정기런에서 출석을 시작했고, 취소·삭제되지 않았으며 종료 시각이 지났고 아직 출석을 닫지 않은 일정만 처리한다. 미확인은 불참으로 바꾸고 기존 출석·지각·불참은 유지한다. 예약 작업은 1분 간격이므로 DB 상태 반영까지 최대 약 1분의 간격이 있다. 출석 조회·처리 때도 종료 함수를 실행한다. DB 트리거가 종료 시각 이후 새 코드 출석 인증과 출석 시작을 차단한다. 운영진의 수동 정정은 유지한다.

출석을 한 번도 시작하지 않은 일정은 자동으로 불참 처리하지 않는다. 일정 종료 시간을 수정하면 현재 저장된 종료 시각을 기준으로 판단한다.

## 참가 선택 흐름

- 처음 ‘참가’를 누르면 선택 모드가 된다. 그룹별 현재 인원이 표시된다.
- 그룹 선택·해제는 임시 상태다. 최종 참가를 눌러야 POST 요청을 보낸다.
- 아무 그룹도 선택하지 않으면 경고 팝업을 표시하고 신청 전 상태로 돌아간다.
- 신청 뒤 ‘변경’을 누르면 다른 그룹은 변경, 내 그룹 선택은 취소 대기가 된다.
- 취소 대기에서 그룹을 다시 선택하면 참가 표시로 돌아간다. 기존 신청이 있으면 최종 저장은 PATCH로 처리한다.
- 최종 ‘참가 취소’를 누를 때만 DELETE한다. 선택 닫기는 서버를 변경하지 않는다.
- 신청 마감·정원·그룹 잠금·취소 기한은 기존 서버에서 다시 검사한다.
- 정기런은 그룹이 필요하다. 그룹이 없는 번개런·이벤트는 기존 무그룹 참가를 ‘자유 참가’ 선택으로 표시한다.

관리자·운영진은 출석 영역의 ‘출석 · 참가 명단’을 열어 그룹별 인원과 이름을 확인하고 출석 시작 후 상태를 선택한다. 출석 종료 후에도 기존 수동 정정 권한은 유지한다.

## 관리 권한

| 계정 | 회원 목록 | 변경 | 시즌·활동 점수 | 관리자 운영 설정 |
|---|---|---|---|---|
| 관리자 | 모든 계정 | 기존 권한 | 가능 | 가능 |
| 회장 | 관리자 제외 | 기존 권한 | 가능 | 불가 |
| 부회장·운영진 | 관리자 제외 | 읽기 전용 | 불가 | 불가 |
| 일반 회원·게스트 | 불가 | 불가 | 불가 | 불가 |

관리자 계정 숨김은 서버 조회와 RLS에서 적용한다. 관리자는 다른 등급으로 내릴 수 없는 기존 정책을 유지한다. 회원·운영진 목록은 별도로 구분한다. 관리자 탭에서 운영 상태를 관리하며 일부 제한 기능을 일정 / 접속 / 내 정보 탭으로 나눠 선택한다. 탭을 바꿔도 다른 탭의 선택은 유지된다.

시즌 관리는 생성, 시즌 설정은 이름·기간·공개·상태·현재 시즌 지정이다. 현재 시즌 지정은 오늘을 포함하는 공개 시즌만 가능하며 다른 진행 시즌은 예정으로 전환된다. 환경 설정은 활동 점수와 최소 활동 기준이다.

## 일정·댓글·버튼

일정 유형을 바꾸면 불러온 정기런 내용과 그룹을 초기화하고 날짜·모집 시간은 유지한다. 날짜는 달력, 시간은 24시간 시·분 선택으로 분리한다. 기존 API의 한국 시간 형식으로 결합해 제출한다.

공지·댓글·답글에 작성 시각을 표시한다. 본인 삭제는 목록에서 숨기며, 다른 사람이 단 답글은 유지한다. 운영진의 타인 글 삭제는 삭제된 댓글 표시를 남기고 내용은 응답에서 제거한다. 회원 탈퇴로 작성자가 익명화되어도 본인 삭제 글은 다시 나타나지 않는다. 과거 삭제 글은 삭제 주체 기록이 없으므로 기존 삭제 표시를 유지한다.

버튼은 배경·테두리·활성/비활성·위험 상태를 구분한다. 선택된 페이스 그룹은 연한 초록과 테두리 및 텍스트로 표시한다.

## 검증

- 릴리스 테스트 47개, ESLint, TypeScript 포함 프로덕션 빌드 통과.
- 실제 서버 페이지와 설정 API를 모의 DB로 실행해 관리자 숨김·운영진 읽기 전용·운영 설정 직접 요청 차단 확인: node scripts/test-admin-directory.mjs.
- 추적 삭제 회귀 테스트 통과: node scripts/test-tracking-deletion.mjs.
- 실제 React 컴포넌트 + 메모리 가상 응답으로 그룹 미선택 팝업 / 선택 미저장 / 최종 POST·PATCH·DELETE / 취소 대기 복원 / 그룹별 명단·지각 처리 / 유형 초기화 / 날짜 제출값 / 탭별 제한 선택 유지 확인.
- 6개 화면 × 320/360/390/430/768/1024/1440px, 42개 조합에서 가로 넘침 없음.
- 동작 미리보기: node scripts/preview-activity-workflow.mjs, http://localhost:3102 (운영 DB 접근 없음).

운영 DB SQL 실행과 실제 cron 자동 종료, 로그인된 실제 계정의 사용자 흐름, 휴대전화 실기기는 아직 검증하지 않았다.

## SQL 적용 후 확인

1. 관리자·회장·부회장·일반 운영진으로 회원 목록과 메뉴 차이 확인.
2. 그룹 선택 후 닫으면 신청되지 않음 → 재선택 후 최종 참가 → 변경 → 취소 확인.
3. 테스트 정기런에서 출석 시작, 일부 출석·지각 지정 → 종료 시각 이후 미확인만 불참 처리·출석 종료 확인. cron 최근 실행 결과도 조회.
4. 본인 공지 삭제는 사라지고 운영진의 타인 댓글 삭제는 삭제 표시가 남는지 확인.
5. 시즌 설정과 관리자 일부 제한의 각 탭 저장·새로고침 후 유지 확인.
