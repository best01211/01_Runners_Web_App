# 제품 안정화 변경 — 2026-10-12

위치 추적을 제외한 운영 기능의 배포 차단 문제를 수정했다. 애플리케이션과 DB 변경을 함께 적용해야 한다. 운영 Supabase에 SQL을 실행하거나 실제 회원 정보를 변경하지 않았다.

## 수정 내용

- 가입 승인 RPC의 NULL 역할 우회를 차단했다. 정지·제한·탈퇴·대기·프로필 없는 계정과 익명 역할의 직접 호출을 거절한다.
- 모든 일정 응답에서 출석번호를 제거했다. DB 직접 조회도 출석번호 열 권한을 회수하고 안전한 열만 허용한다. 운영자는 출석 API에서만 번호를 조회한다.
- 삭제 댓글 본문을 API에서 비우고 직접 DB 조회에서 숨긴다. 댓글 수정 권한은 공지 설정 권한과 별도로 검사한다. 잘못된 JSON 입력은 400 응답으로 처리한다.
- 비공개·숨김 시즌을 일반 회원 조회에서 제외한다. 기본 시즌 변경과 시즌 생성을 한 트랜잭션으로 처리하고 동시 변경을 직렬화한다.
- 참가 신청·페이스 그룹 검증·배정을 같은 RPC로 처리한다. 정기런의 그룹 선택을 DB에서도 강제한다. 그룹 변경과 참가 취소는 출석 처리와 같은 일정 행 잠금을 사용한다.
- 출석 시작 시 참가 취소·그룹 변경 잠금을 저장하고 기존 출석 세션에도 적용한다. 출석 종료 후 미확인 상태로 되돌리는 변경을 거절한다.
- 번개런 생성자의 자동 참가를 DB 트리거로 이동했다. 참가 저장 실패 시 일정 생성도 취소된다. 관리자 역할은 기존 정책대로 자동 참가 대상에서 제외한다.
- 운영진 정원 제외 설정을 DB 신청 검사와 화면 인원·신청 버튼에 반영한다.
- 회원 역할·상태 변경을 DB RPC로 이동하고 변경 이력을 저장한다. 탈퇴 대기·완료 계정 및 미승인 계정의 임의 변경, 탈퇴 상태 직접 지정, 운영진의 상위 역할 대상 변경을 차단한다. 이력 저장 실패도 회원 변경을 롤백한다.
- 정기런 그룹 생성 화면, 회원 본인 출석 결과, 출석 상태 주기적 조회를 연결했다. 주요 입력 화면에 통신 실패 안내와 처리 중 버튼 제한을 적용했다.
- 일정 입력·표시는 한국 시간으로 통일했다. 시간대 없는 입력은 명시적으로 +09:00으로 해석하고 UTC로 저장한다. 잘못된 날짜·시각은 거절한다.
- 로그인 이동값을 내부 경로로 제한했다. 가입 완료·인증 성공·실패 안내와 가입 링크를 추가했다. 로그인·가입·로그아웃 및 운영 쓰기 API에서 같은 Origin을 확인한다.
- 사용자 세션의 직접 프로필/일정/참가 쓰기 권한을 회수했다. 앱의 허용된 API와 보안 정의 RPC를 통해서만 변경한다.

## DB와 앱 적용 순서

1. 검증 환경에서 기존 기본 스키마와 003~008 적용 상태를 확인한다. 초기 profiles/schedules/참가 스키마는 이 저장소에 없으므로 운영 스키마를 기준으로 확인해야 한다.
2. DB 백업 후 `supabase/migrations/009_product_stabilization.sql` 전체를 실행한다. 하나의 트랜잭션이며 오류가 나면 변경 전체가 취소된다. 기존 테이블과 활동 기록을 삭제하지 않는다.
3. PostgREST 스키마 캐시가 갱신됐는지 확인한 뒤 해당 앱 버전을 배포한다. 새 앱의 신청·회원 변경·시즌 생성은 009 RPC가 필요하다.
4. 009는 기존 앱의 사용자 세션 직접 그룹 UPDATE를 차단한다. DB 적용과 앱 교체 사이에는 쓰기 작업을 점검 모드로 제한한다. 복귀 시에도 보안 수정과 새 RPC를 포함한 앱을 사용한다. 취약한 DB 권한으로 되돌리는 방식은 권장하지 않는다.
5. 실제 Auth 가입 프로필 생성 트리거, 이메일 확인·복구 설정, 이미지 Storage, 기존 RLS 정책과 권한이 이 변경과 함께 작동하는지 전용 테스트 계정으로 확인한다.

이미 저장된 시간대 오류, 잘못된 페이스 그룹 배정, 단순 상태 변경으로만 처리된 탈퇴 기록은 자동 보정하지 않는다. 실제 의도와 감사 기록을 확인한 뒤 별도 데이터 정리가 필요하다.

## 로컬 검증

```powershell
npm run test:auth
npm run test:release
npm run test:release-db
npm run test:stabilization-db
npm run test:tracking
npm run lint
npx tsc --noEmit --incremental false
npm run build
```

DB 테스트는 기존 로컬 PGlite 설치 경로를 사용한다. 새 환경에서는 먼저 다음을 실행한다.

```powershell
npm install --prefix .test-output/sql-qa --no-audit --no-fund --ignore-scripts --cache .npm-cache @electric-sql/pglite@0.5.8
```

인증 단위 테스트 5개, 출시/안정화 단위 테스트 12개, 기존 출시 DB 32개, 신규 안정화 DB 46개가 통과했다. 추적 엔진 회귀 테스트 30개도 통과했다. ESLint·TypeScript·프로덕션 빌드가 통과했다. DB 테스트는 실제 PostgreSQL 엔진의 로컬 fixture이며 운영 Supabase 설정이나 실사용 화면 검증을 대신하지 않는다.

## 실제 배포 전 확인

- 승인·정지·제한 계정으로 화면과 직접 RPC 권한을 확인한다. 일반 회원은 출석번호를 읽을 수 없어야 한다.
- 정기런 생성 → 그룹 추가 → 참가 → 그룹 변경 → 출석 시작 → 번호 인증 → 종료 → 랭킹 반영을 실행한다. 다른 기기에서 시작·종료 상태가 갱신되는지 확인한다.
- 출석 시작과 취소 요청을 동시에 보내도 출석 이후 취소가 저장되지 않는지 실제 서버에서 확인한다.
- 한국 19:00 일정이 서버 시간대와 무관하게 한국 19:00으로 표시되는지 확인한다.
- 삭제 댓글의 네트워크 응답에 본문이 없고 비공개 시즌이 일반 회원에게 보이지 않는지 확인한다.
- 탈퇴 신청 → 반려 → 재신청 → 승인·Auth 삭제 재시도 흐름을 전용 계정으로 확인한다.

독립 게시판, 페이서 지정, 시즌 수정, 가입 거절 재신청, 예약 점검은 이번 안정화에서 새로 구현하지 않았다. 이 기능들을 출시 범위에 포함하려면 추가 작업이 필요하다.
