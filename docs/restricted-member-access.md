# 제한과 정지의 구분

015 이후 `016_restricted_member_access.sql`을 전체 실행한 뒤 앱을 새로고침한다. 실제 회원의 상태는 이 SQL에서 변경하지 않는다.

| 상태 | 서비스 조회 | 신규 활동 | 기존 참가 처리 | 내 정보 |
|---|---|---|---|---|
| 활성 | 가능 | 역할별 허용 | 가능 | 가능 |
| 제한 | 일정·공지·댓글·랭킹·추적 조회 | 신청·그룹 변경·일정 생성/수정·그룹 추가·댓글 작성 및 운영 작업 차단 | 기존 참가 취소·출석 인증 가능. 마감/출석 잠금은 계속 적용 | 수정·비밀번호 변경·프로필 사진·탈퇴 신청 가능 |
| 정지/탈퇴 완료 | 차단 | 차단 | 차단 | 서비스 화면 차단. 기존 비밀번호 복구 경로는 유지 |
| 탈퇴 처리 대기 | 차단 | 차단 | 차단 | 상태 안내·로그아웃. 기존 비밀번호 복구 경로는 유지 |

제한 계정은 본인 댓글을 삭제할 수 있지만 운영진의 다른 회원 댓글 삭제 권한은 사용할 수 없다. 제한 운영진·관리자의 관리 권한도 차단한다. 제한 계정은 새 로그인도 가능하다. 탈퇴 대기는 `withdrawal_requests.status='pending'`으로 별도 판별한다.

기존 `is_active_member`는 신규 쓰기 검사의 활성 조건으로 유지하고, 조회·개인정보 변경·참가 취소·본인 출석에는 `can_read_member`를 사용한다. 조회 정책의 다른 필터(삭제 본문·비공개 시즌 등)는 유지한다. 직접 DB INSERT/UPDATE/DELETE 권한을 추가하지 않는다.

탈퇴 신청 당시의 활성/제한 상태를 요청에 저장하고 반려 시 그 상태로 복원한다. 기존 탈퇴 요청의 이전 상태는 기존 동작에 맞춰 활성으로 기본 설정한다.

API·프록시·페이지와 DB 검사에 정책을 반영했다. DB 테스트 27개에서 제한 회원/운영진의 조회·출석 인증·참가 취소·정보 수정 허용, 신규 신청·그룹 변경·출석 운영 차단, 정지 차단, 탈퇴 대기 차단·반려 복원 및 직접 쓰기 차단을 확인했다.
