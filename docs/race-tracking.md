실제 대회 연결 기능은 [수동 계측 단계 문서](race-tracking-live.md)를 참고한다.

# Race Tracking — Mock 구현 단계

## 현재 제공 범위

- 로그인·승인된 활성 회원용 `/tracking/demo`
- 기존 이벤트 상세 → `/schedules/{scheduleId}/tracking/demo`
- 대시보드 진입 링크
- 사용자 제공 서울레이스 GPX 경로와 가상 선수 6명, 지연·누락·DNF·DNS 시나리오
- 재생·일시정지·1/10/60배속·시간 이동
- Leaflet 지도, 선수 선택, 계측 기록·예상 거리·페이스·완주 시간·신뢰도
- GPX 단일 트랙 구간 및 GeoJSON LineString 코스 유틸리티

선수·계측·출발 시각은 가상이다. 코스 좌표는 사용자 제공 서울레이스 GPX를 사용한다. Mock은 회원 DB, 완주 결과, 활동 랭킹에 기록하지 않는다.
외부 Timing Provider 수집, GPS 위치 전송, 신규 DB 마이그레이션은 이 단계에 포함하지 않는다.

## 확인 주소

`npm run dev` 실행 후 로그인한다. 대시보드의 **선수 추적 데모**를 선택한다.
기존 `event` 일정이 있으면 상세의 **추적 데모 보기**로도 진입할 수 있다.
취소·삭제된 이벤트 및 다른 일정 유형은 이벤트별 데모에서 제외한다.
이벤트별 데모 조회는 사용자 세션 Supabase 클라이언트와 기존 RLS를 사용한다.

독립 데모를 별도로 두었으므로 실제 이벤트나 참가 신청이 없어도 검증할 수 있다.
비로그인 사용자는 기존 인증 정책에 따라 로그인 페이지로 이동한다.

## 계산 규칙

거리: m. 페이스: 초/km. 저장 시각: ISO UTC. 화면 시각: Asia/Seoul.

초기 페이스는 목표 기록 → 개인 목표 페이스 → 페이스 그룹 → 기본 6:00/km 순이다.
실측 기록 쌍이 있을 때만 최근 최대 3개 구간 페이스를 0.5/0.3/0.2로 가중 평균한다.
구간이 부족하면 가중치를 재정규화한다. 예정 출발을 실측 START로 간주하지 않는다.
초기 추정, 실측 START만 있는 경우에는 낮은 신뢰도를 표시한다.

미래·미수신·중복·거리 역전·시간 역전·종목 거리 초과 기록을 제외한다.
실측 구간 페이스가 2:00/km 미만 또는 20:00/km 초과면 해당 기록을 기준점으로 사용하지 않는다.
이 범위는 초기 방어값이며 실제 대회 운영 전 종목별로 검토해야 한다.

마지막 기록 이후 45분까지 외삽하고 이후 위치를 고정한다.
미실측 초기 추정도 같은 상한을 사용한다. 실제 FINISH 없이 결승점을 추정하면 완주 계측 대기다.
DNS는 출발점, DNF는 마지막 계측점에 고정한다.
실제 FINISH가 있을 때만 finished 상태와 측정된 완주 소요 시간을 표시한다.

신뢰도는 계측 이후 5분 이하 HIGH, 15분 이하 MEDIUM, 이후 LOW다.
이는 검증된 정확도 확률이 아닌 계측 최신성 지표다.

공식 거리와 좌표 누적 거리는 비율로 매핑한다.
데모는 서울레이스 GPX의 918개 좌표를 하프 거리 21.0975km에 매핑한다.
이는 거리 기준 시뮬레이션이며 공식 코스 인증이나 실제 경기 출발 시각을 의미하지 않는다.
실제 GPX 도입 시 공식 거리와의 차이 및 연속성을 운영진이 확인해야 한다.
GPX는 브라우저 DOMParser를 사용하며 단일 trkseg만 지원한다.
GeoJSON Feature 또는 LineString을 지원하고 MultiLineString은 거절한다.

마커 이동은 코스 위 거리로 보간한다. 시간 이동은 즉시 반영한다.
모션 감소 설정에서는 애니메이션을 생략하며, 화면 폭 변경 시 코스를 다시 맞춘다.
목록·상세는 지도 로드 실패 시에도 사용할 수 있다.

## Provider 경계

`TimingProvider`는 getRaceInfo / getRunner / getCheckpoints 계약을 제공한다.
Mock은 가상 시각에 따라 이미 통과하고 수신된 체크포인트만 반환한다.
서버 타이머나 DB 쓰기를 사용하지 않아 같은 시각에서 같은 결과를 재현한다.
현재 데모의 기준 데이터는 브라우저에서 생성하며 외부 요청/폴링 API를 사용하지 않는다.

실제 연동 시 서버에서 외부 결과를 검증·정규화하고 대회 단위로 조회하도록 확장한다.
Provider 승인 전에는 SmartChip 등의 공개 HTML 엔드포인트를 호출하지 않는다.

## 지도

Leaflet 1.9.4를 클라이언트에서만 로드한다.
기본은 배경 타일 없이 코스와 선수만 표시한다.
사용자가 배경 지도 표시를 선택하면 OSM 표준 타일을 사용하고 출처를 표시한다.
이 데모는 미리 가져오기·일괄 다운로드·오프라인 타일 저장을 수행하지 않는다.
운영 대회 트래픽을 받기 전에는 타일 공급자·정책·용량을 별도로 결정해야 한다.

https://operations.osmfoundation.org/policies/tiles/

## 검증

- `npm run test:tracking`: TypeScript를 별도 출력 폴더에 컴파일한 후 Node 내장 테스트 실행
- `npx tsc --noEmit --incremental false`: 전체 타입 검사
- `npm run lint`: 전체 ESLint
- `npm run build`: Next.js 프로덕션 빌드

테스트 산출물 `.test-output`과 로컬 npm 캐시 `.npm-cache`는 Git·ESLint에서 제외한다.
테스트 산출물은 앱 TypeScript 검사에서도 제외한다.

## 다음 단계

기존 profiles / schedules / schedule_participations의 초기 DDL·RLS·FK·트리거를 확인한다.
그 후 race_courses / race_entries / runner_checkpoints / race_results와 쓰기 RPC를 확정한다.
기존 참가 신청을 재사용하고 출전 정보 등록 UI를 별도 패널로 연결한다.
완주 결과는 실측 또는 운영진 검증에 한정하며 기존 출석 점수 정책을 자동 변경하지 않는다.
현재 작업 트리의 기존 변경사항은 유지한다.

실측 START가 없는 FINISH는 위치상 완주로 표시하지만 실제 넷타임을 만들지 않는다.
예상 완주 시간에는 실측 출발/예정 출발 기준을 구분해 표시한다.

데모는 출발 후 45분에서 시작하고 총 3시간 범위에서 재생한다.
체크포인트는 START / 5K / 10K / 15K / 20K / 21.0975km FINISH다.
선수마다 다른 가상 구간 페이스로 이동하고 누락·DNF·DNS 시나리오를 유지한다.
선택 선수는 검은 테두리와 이름 말풍선으로 표시하며 코스는 흰 테두리를 두른 녹색 선으로 표시한다.

### 2026-10-07 지도 가독성 조정
배경 지도를 기본 표시하되 타일에만 회색조와 낮은 불투명도를 적용합니다. 코스는 흰 테두리와 남색 선, 선수는 색상 마커로 강조합니다. 5km 간격 표시는 코스 거리 안내이며 실제 계측소를 뜻하지 않습니다. 데모와 라이브가 같은 지도 스타일을 사용하며 모바일 지도 높이를 확대했습니다.
