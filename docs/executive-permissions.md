# 운영진 직책별 권한

017까지 적용한 뒤 Supabase SQL Editor에서 `supabase/migrations/018_executive_permissions.sql` 전체를 실행하고 웹을 새로고침한다. 회원 데이터나 직책은 자동 변경하지 않는다. SQL은 반복 실행할 수 있다.

| 권한 | 일반 운영진 | 부회장 | 회장 | 관리자 |
|---|---|---|---|---|
| 일정·정기런 양식·출석·댓글·가입 승인 관리 | 가능 | 가능 | 가능 | 가능 |
| 전체 점검 중 접속 | 불가 | 가능 | 가능 | 가능 |
| 관리자 화면·서비스 설정·시즌 생성·추적 관리 | 불가 | 불가 | 가능 | 가능 |
| 회원 상태·등급 변경 및 회원 삭제 | 기존 운영진 범위 | 기존 운영진 범위 | 가능 | 가능 |
| 관리자 계정 변경·신규 관리자 지정 | 불가 | 불가 | 불가 | 가능 |

기존 운영진의 회원 변경 RPC는 일반회원·게스트의 일부 항목에만 한정된다. 전체 회원 관리 화면은 회장·관리자에게만 제공된다. 관리자 등급을 낮추거나 관리자 계정을 삭제하는 것은 기존 보호 규칙대로 누구에게도 허용되지 않는다. 본인 권한·상태 변경도 기존대로 차단한다.

회장은 role=staff, staff_position=president로 유지된다. 별도의 관리자 계정으로 변환하지 않으므로 관리자가 회장을 다른 직책이나 일반회원으로 변경할 수 있다. 회장에게 관리자 등급을 직접 부여하면 기존 관리자 등급 보호 규칙이 적용된다.

일부 제한에서는 회장·관리자 접속이 항상 허용된다. 부회장·일반 운영진의 접속 여부는 기존 운영진 허용 체크박스로 함께 설정한다. 개별 기능 차단은 접속 허용과 별도로 계속 적용된다. 계정 정지·제한·승인 상태에 따른 기존 제한도 유지한다.

## 확인

1. 관리자로 운영진 계정을 일반 운영진·부회장·회장으로 각각 지정한다.
2. 전체 점검에서 일반 운영진은 제한 화면으로 이동하고, 부회장·회장·관리자는 접속되는지 확인한다.
3. 회장 계정에서 관리자 메뉴, 서비스 설정, 시즌 생성, 추적 관리가 보이는지 확인한다.
4. 회장 계정에서 관리자 계정의 변경 항목이 비활성이고 관리자 지정 옵션이 없는지 확인한다.
5. 관리자로 회장의 직책을 부회장 또는 일반 운영진으로 변경하고, 해당 계정에서 관리자 기능이 더 이상 허용되지 않는지 확인한다.
6. 서비스 상태를 정상으로 복구한다.

로컬 DB 검증: `npm run test:executive-permissions-db`. 전체 점검·일부 제한, 회원 변경, 관리자 보호, 회장 권한 회수, 시즌 생성, 추적 관리 권한, 회원 삭제를 검증한다.
