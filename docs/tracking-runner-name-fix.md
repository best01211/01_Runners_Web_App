# 선수 이름 등록 오류 수정

실제 DB의 `tracking_race_entries.runner_name`은 기본값 없는 필수 컬럼이지만,
기존 등록 요청과 030 마이그레이션의 함수는 이름을 저장하지 않았다.
이 구조에서는 선수 등록 시 NOT NULL 제약으로 저장이 실패한다.

앱은 선택한 회원의 `profiles.name`을 서버에서 조회하여 `runnerName`으로 전달한다.
참가자 선택과 선수 추적 화면에도 닉네임 대신 회원 이름을 표시한다.
동명이인의 출전 정보가 섞이지 않도록 내부 회원 연결은 UUID를 유지한다.

DB에는 `supabase/migrations/033_tracking_runner_names.sql`을 적용한다.
기존 컬럼이 있는 DB와 없는 DB를 모두 지원하며, 기존 선수 이름이 비어 있으면
연결된 회원 이름으로 채운다. 등록 함수도 회원 이름을 직접 조회해 저장하므로
클라이언트가 보낸 이름으로 다른 이름을 저장할 수 없다.
기존 권한, 그룹, 중복 배번호, 출발 후 수정 잠금은 유지한다.

검증:

- `node scripts/test-tracking-staff-api.mjs`: 회원 이름 전달, 이름 위조 방지,
  빈 이름·조회 실패 차단, 닉네임 대신 이름 표시.
- `node scripts/test-tracking-timing-database.mjs`: 필수 이름 누락 오류 재현,
  수정 후 등록·수정, 기존 데이터 보정, 마이그레이션 재실행, 기존 권한과 계측 검증.

로컬 테스트는 메모리 DB를 사용한다. 운영 DB에 마이그레이션을 적용하거나
앱을 배포하는 작업은 포함하지 않는다.
