# 관리자 이용 모드

- 운영 메뉴와 내 정보에서 관리자 모드 ↔ 일반 모드를 전환한다. 성공 시 대시보드를 새로 열어 이전 모드의 페이지 캐시를 제거한다.
- 일반 모드는 `role=staff`, `staff_position=staff`인 일반 운영진이다. 관리자 전용 API·DB 기능과 서비스 점검 예외는 적용되지 않는다. 기존 RLS 정책은 수정하지 않는다.
- `admin_account`는 원래 관리자 계정임을 보존한다. 일반 모드에서도 계정 삭제·탈퇴·강등은 보호한다. 활성·승인 상태와 탈퇴 신청 여부를 서버와 DB에서 검증한 본인만 전환한다.
- 모드는 계정 단위로 모든 기기에 적용된다. 같은 브라우저의 다른 탭은 storage 이벤트, 다른 기기는 기존 서비스 상태 확인 주기(10초)에서 화면을 갱신한다. 서버 권한은 매 요청의 현재 DB 상태로 판정한다. 이미 실행 중인 요청을 취소하는 기능은 아니다.
- 전체 점검 중 일반 모드에서도 점검 화면에서 관리자 모드로 돌아갈 수 있다. 이용 정지·신청 제한·미승인 계정에는 이 복귀 권한을 부여하지 않는다.

## 신청·출석

사용자 확인에 따라 **일반 모드는 실제 신청·출석**이다. 기존 운영진과 동일하게 공개 명단·정원 규칙·출석 집계에 반영된다. 관리자 모드에서의 신청만 기존 `admin_schedule_tests`를 사용하는 비공개 테스트다. 두 기록은 합치거나 자동 전환하지 않는다. 일반 모드의 실제 기록은 관리자 모드로 돌아가도 삭제하지 않는다. 랭킹·회원 표시에는 기존 현재 역할 기반 정책이 계속 적용되므로 관리자 모드에서는 관리자 제외 정책이 적용된다.

## 적용과 검증

배포 전에 `supabase/migrations/031_administrator_modes.sql`을 적용해야 한다. 031 미적용 시 프로필 조회는 기존 컬럼으로만 재시도하며 모드 전환 버튼을 숨긴다. 일반적인 프로필 조회 오류는 503으로 처리해 로그인·승인 대기 화면의 반복 이동을 막는다. 모드 전환을 사용하려면 DB를 먼저 적용한다. 이 작업은 로컬 코드·테스트만 수행하며 원격 DB에는 적용하지 않는다.

`npm run test:administrator-modes`는 실제 API 핸들러의 권한/입력/위조 대상 방지와 PostgreSQL에서 권한 강등·복귀·점검·계정 제한·계정 보호·실제 참가 기록 유지·기존 RLS 정의 불변을 확인한다. DB 테스트는 기존 `.test-output/sql-qa`의 PGlite 런타임을 사용한다. Vercel 배포 후 관리자/일반 모드로 참가, 출석, 점검 중 복귀를 별도 확인한다.
