# 이벤트 참석 신청

## DB 적용
1. 기존 022까지 적용된 DB에서 `supabase/migrations/023_event_participation.sql` 전체를 실행한다. 트랜잭션이므로 일부 구문만 실행하지 않는다.
2. `supabase/diagnostics/event-participation.sql`로 컬럼 4개, RPC 실행 권한(인증 사용자만), 트리거 3개와 이벤트 설정을 조회한다.
3. 기존 이벤트는 행사 이벤트로 분류하고 기존 참가자는 참석으로 이관한다. 기존 이벤트의 페이스 그룹 배정은 해제하며 그룹 자체나 참가 기록은 삭제하지 않는다. 정원이 없던 행사는 임의의 숫자를 지정하지 않으므로 운영진이 정원을 설정해야 한다. 기존 모집 시작 시각이 비어 있으면 함께 설정한다.

## 동작
- 대회 이벤트: 주자·응원단 중 선택. 합산·유형별 정원 제한 없음. 모집 기간 안에서 참석 유형 변경 가능하며 기존 출석 시작 후 변경 제한 유지.
- 행사 이벤트: 페이스 그룹 없이 참석 신청. 모집 시작 시각과 선착순 정원 필수. 운영진도 정원에 포함한다.
- 정원에 최초 도달하면 일반 신청이 영구 마감된다. 취소·삭제로 인원이 줄거나 정원을 늘려도 일반 신청을 다시 열지 않는다. 새 모집이 필요하면 새 이벤트를 만든다.
- 관리자·운영진(회장·부회장 포함)은 이름 검색 후 실제 계정을 선택하여 수동 추가할 수 있다. 동명이인은 닉네임·아이디를 확인한다. 행사 정원을 초과할 수 없으며 대회는 제한 없다.
- 수동 추가는 모집 종료·출석 시작·일정 종료 이후에도 가능하되 취소된 일정에는 불가. 이는 참가 등록이며 출석 처리와 구별된다. 출석 중 추가하면 미확인, 출석 종료 후 추가하면 기존 원칙에 따라 불참 기록을 만들며 운영진이 출석 화면에서 수정할 수 있다.
- 관리자 계정 자체, 미승인·정지·신청 제한·탈퇴 신청 중 계정은 참석자로 추가할 수 없다. 게스트는 해당 일정에서 허용한 경우만 가능하다.
- 기존 참가 취소 기한·출석 잠금은 유지한다. 점검 중 참석 신청 차단은 일반 신청과 운영진 추가에 동일하게 적용한다. 기존 취소 허용은 유지한다.
- 신청 인원은 저장 직후와 15초마다 새로 조회한다. DB에서 일정 행을 잠근 뒤 정원 검사·등록·최초 마감 기록을 같은 트랜잭션에서 처리한다. 기존 페이스 그룹 RPC로 이벤트 신청을 우회하는 것도 트리거가 차단한다.
- 신청자가 있는 일정은 이벤트/다른 유형 간 전환 및 대회/행사 분류 변경이 불가하다. 기존 참가자 배정을 보호하기 위함이다.

## 확인
1. 행사 정원 2명 → 두 명 신청 → 첫 정원 마감 → 한 명 취소 → 표시 1명, 일반 신청 버튼 비활성 유지.
2. 운영진 이름 검색 → 동명이인 계정 선택 → 빈자리 추가 → 다시 정원 2명. 세 번째 추가는 DB에서도 차단.
3. 모집 종료 시각을 지난 뒤 운영진 추가가 가능한지 확인.
4. 대회에서 주자·응원단 신청 및 유형 변경, 정원 입력 없음, 페이스 그룹 없음 확인.
5. 일반회원의 수동 추가 API 호출 거절, 운영진 검색 결과·명단의 관리자 계정 숨김 확인.

## 개발 검증
- `npm run test:release`, `node scripts/test-event-participation-api.mjs`, 린트·빌드.
- 운영 DB와 분리한 실제 PostgreSQL 엔진 검증: 먼저 `npm install --prefix .test-output/event-db-runtime --no-save --ignore-scripts @electric-sql/pglite@0.5.10`, 이후 `node scripts/test-event-participation-sql.mjs`.
- 임시 테스트 엔진은 프로젝트 의존성에 추가하지 않았다. 실제 브라우저 UI 검증은 가상 데이터로 수행했다. 운영 DB SQL 적용과 실제 계정 최종 확인은 별도이다.
