# 서비스 점검 및 기능 제한

## 적용

기존 016 SQL까지 적용한 뒤 Supabase SQL Editor에서 `supabase/migrations/017_service_feature_restrictions.sql` 전체를 실행한다. 실행 후 웹을 새로고침한다. 017은 다시 실행할 수 있다.

## 관리자 설정

관리자 페이지의 서비스 상태에서 운영 모드를 선택한다.

- 정상: 서비스 제한을 해제한다.
- 전체 점검: 승인된 관리자·회장·부회장만 접속할 수 있다.
- 일부 제한: 일정 생성, 댓글 작성·수정, 참석 신청·그룹 변경, 접속, 내 정보 수정을 각각 선택하여 차단한다.

접속 금지를 선택하면 접속을 허용할 등급을 고른다. 운영진, 페이서, 일반회원, 게스트를 각각 선택할 수 있으며 관리자·회장은 항상 허용된다. 허용 등급 중 하나에 해당하면 접속할 수 있다. 계정 정지·탈퇴 상태 등의 기존 계정 제한은 그대로 적용된다.

이미 접속한 계정도 화면이 보이는 동안 10초마다 접속 권한을 재확인한다. 탭 복귀 및 화면 이동 시에도 확인하며, 접속이 차단되면 제한 안내 화면으로 이동한다. 브라우저에서 절전·백그라운드로 정지한 탭은 복귀할 때 확인한다. 로그인 세션을 삭제하지 않으며 서버의 요청 차단은 즉시 적용된다. 접속 검사에서는 서버 권한으로 설정을 읽는다. 차단된 회원의 RLS가 설정 행을 숨기는 경우에도 정상 상태로 잘못 판단하지 않는다.

회원 관리의 **페이서 지정**은 접속 정책에 사용하는 회원 구분이다. 일정별 페이서 지정 및 랭킹 가산점과는 별개이며 기존 일정 기록을 자동 변환하지 않는다.

일부 제한된 기능은 화면에 그대로 표시한다. 실행 버튼을 누르면 점검 안내 팝업이 열리며 요청은 전송되지 않는다. 서버와 DB에서도 기능 차단은 유지된다.

접속 허용과 기능 차단은 별도다. 접속이 허용된 운영진·관리자에게도 선택한 기능 차단은 적용된다. 관리자·회장의 서비스 설정 변경은 계속 가능하다.

참석 제한 중에도 기존 참가 취소와 출석 인증은 가능하다. 댓글 제한 중에도 댓글 삭제는 가능하다. 내 정보 제한에는 비밀번호 변경과 프로필 사진 저장이 포함된다. 일정 생성 제한은 기존 일정 수정에는 적용되지 않는다.

시작·종료 시각은 한국 시간 기준 안내용이다. 저장 즉시 상태가 적용되며 시간에 따른 자동 시작·해제는 하지 않는다. 해제하려면 정상으로 저장한다.

관리자 등급은 다른 등급으로 변경할 수 없다. 화면에서 변경을 막으며 DB 트리거도 동일한 규칙을 적용한다. 신규 관리자 지정 시 변경 불가 안내를 확인해야 한다.

## 확인 순서

1. 일반회원 계정의 페이서 지정을 켜고, 일부 제한에서 접속 금지와 페이서 허용만 선택한다. 페이서 회원은 접속되고 일반회원은 제한되는지 확인한다.
2. 운영진 허용을 끄고 운영진 계정으로 제한 화면을 확인한다. 관리자 계정은 설정에 계속 접속할 수 있어야 한다.
3. 접속 금지를 해제하고 나머지 기능을 하나씩 선택한다. 일정 생성, 댓글 작성·수정, 참석 신청·그룹 변경, 내 정보 저장이 선택한 항목에만 막히는지 확인한다.
4. 전체 점검에서는 일반회원·페이서가 제한되고 부회장·회장·관리자는 접속되고 일반 운영진은 차단되는지 확인한다.
5. 다른 관리자 계정의 등급 선택이 비활성인지 확인하고, 정상으로 저장하여 기능을 복구한다.

자동 DB 검증은 로컬 임시 DB에서 수행한다. 실제 Supabase 적용과 계정별 웹 확인은 위 순서대로 진행한다.

018부터 적용되는 직책별 세부 규칙은 `docs/executive-permissions.md`를 따른다.
