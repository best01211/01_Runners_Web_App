# 일정 생성 화면의 페이스 그룹

014 이후 `015_schedule_creation_pace_groups.sql` 전체를 실행한다. 추가되는 열과 함수는 기존 일정·그룹·참가 기록을 변경하지 않는다.

일정 만들기 화면의 **러닝 페이스 그룹 → 페이스 그룹 추가**에서 분·초·거리를 입력한다. 정기런 양식의 **기본 정보 불러오기**를 누르면 그룹도 편집기에 복사된다. 그룹 추가·수정·삭제는 이번 일정에만 반영되며 양식 원본은 유지된다. 정기런 생성은 그룹 한 개 이상이 필요하며 번개런·훈련·이벤트는 선택 사항이다.

POST API는 중복·개수·숫자·단위 검증 후 `creation_pace_groups`를 저장한다. DB INSERT 트리거는 명시된 목록을 우선 사용하고, 목록이 생략된 기존 클라이언트는 정기런 양식의 그룹을 사용한다. 일정과 그룹은 하나의 트랜잭션으로 생성된다. 저장된 생성 시점 목록은 기존 일정 수정 시 자동 재적용하지 않는다.

일정 수정 화면에서는 기존 참가자 배정을 보호하기 위해 그룹을 다시 생성하지 않는다. 기존 일정의 그룹 추가는 상세 화면에서 수행한다.

단위 테스트 30개와 DB 검사 29개가 통과했다. 개별 일정 그룹 우선 적용, 양식 원본 유지, 번개런 그룹 생성, 명시적 빈 목록 처리, 중복 차단과 전체 롤백을 확인했다. 린트·타입 검사·프로덕션 빌드를 확인했다. 운영 DB 적용은 사용자가 진행한다.
